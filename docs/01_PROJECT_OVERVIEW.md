## 1. 개요

Syncattend V3는 **시간 제한 동적 QR 코드**와 교수 단말이 방출하는 **초음파 음향 토큰(Ultrasonic Audio Token)** 을 결합한 이중 인증에, **신원 위조(다계정 대리) 방어 계층**과 **교수 확인 계층**을 더한 스마트 출결·학사관리 플랫폼이다. 사람의 판단이 아닌 **시스템 구조**로 대리 출결을 구조적으로 어렵게 만들고, 교수의 행정 리소스를 절감하며, 수업 시작 시간대의 대규모 트래픽에서도 안정적으로 동작하는 것을 목표로 한다.

- **학생**: **Flutter 네이티브 모바일 앱**으로 QR 스캔과 마이크 기반 음향 토큰 감지를 동시에 수행하여 출석 인증. 위험군(누적 결석 등)에게 인증 직후 실시간 경고 제공.
- **교수**: React 웹 통합 대시보드에서 실시간 출석률·미인증 학생을 확인. 별도 하드웨어 없이 PC 화면(QR)과 스피커(음향 토큰)만으로 운영. Opt-out(결석자만 수동 처리) + Delta Batch UPDATE로 클릭·서버 부하 최소화.

> **핵심 기술 가정(선검증 대상)**: 본 설계의 성패는 "일반 노트북 스피커가 18~20kHz 준-초음파를 안정적으로 방출하고, 다양한 학생 기기 마이크가 강의실 거리·소음 환경에서 이를 복호할 수 있다"는 가정에 달려 있다. 이는 확정 사실이 아니라 **프로젝트 최대 기술 리스크이자 선결 검증 항목**으로, M1~M2 초기에 소규모 실현 가능성 스파이크(feasibility spike)로 우선 검증한다. 준-초음파 신뢰도가 부족하면 **가청 대역 하단(거슬림이 적은 대역)이나 화면 표시 보조 신호**로의 대체안을 함께 준비한다.

## 2. 계층 방어 (핵심 원칙)

어떤 단일 신호도 단독으로 신뢰하지 않고, 다음 계층을 겹친다.

| 계층 | 신호 | 메커니즘 |
|------|------|----------|
| 시간·신원 | 동적 QR | 15초 TTL 회전 토큰 (Redis), 교수 PC 화면 표시 |
| 공간·근접성 | 초음파 음향 토큰 | 18~20kHz nonce, 교수 PC 스피커 방출 → 학생 Flutter 앱 마이크 복호(FFT/대역 필터) |
| 신원(다계정 방어) | 1분 인증 창 + 서버 유일성 + 기기 바인딩 | 약 60초 인증 창, 서버가 "세션당 계정 1회·기기 UUID 1회" 강제, 앱 생성 UUID를 계정에 바인딩 |
| 사람 | 교수 확인 | Opt-out 대시보드, 미인증자는 결석 자동 확정이 아닌 교수 확인·정정·창 연장 대상 |

> QR·음향은 "기기가 강의실에 있다"는 **근접성**만 증명할 뿐 "조작자가 계정 주인인가"라는 **신원**은 증명하지 못한다. 이 신원 문제를 1분 창 + 서버 유일성 + 기기 바인딩으로 방어한다.

## 3. 신원 위조(다계정 대리) 방어 요약

- **1분 인증 창**: 인증은 교수가 여는 약 60초 동안만 가능. "내 출석 → 로그아웃 → 친구 계정 → 재인증" 수법을 시간적으로 어렵게 만든다. 교수가 창을 연장 가능.
- **서버측 유일성 규칙(실질 핵심)**: 서버가 "한 세션당 계정 1회·동일 기기(UUID) 1회 출석"을 강제. 프론트로 우회 가능한 공격을 서버에서 차단.
- **앱 생성 UUID 기기 바인딩**: Flutter 앱이 최초 실행 시 랜덤 UUID를 생성해 iOS 키체인/Android 키스토어(`flutter_secure_storage`·`flutter_udid`)에 저장하고 계정에 바인딩. 하드웨어 ID는 OS가 차단하고 `device_info_plus`의 OS 식별자(IDFV/SSAID)는 재설치·초기화로 변하므로 바인딩 기준으로 부적합 → 보안 목적 `device_info_plus` 미사용.
- **기기 변경 시 재등록**: UUID 소실·기기 교체 시 곧바로 출석 불가, **학교 이메일(@wku.ac.kr) 재인증**으로만 새 기기 재바인딩.
- **프론트엔드는 UX 넛지만**: 하드 쿨타임/세션 잠금은 서버 규칙과 중복이고 정상 사용자 오탐이 커 두지 않는다.
- **생체인증은 선택적 확장**: 1분 창 도입으로 필수 아님. 향후 옵션(Face ID/지문).
- **잔여 공격(여러 폰 지참)**: 소프트웨어로 완전 차단 불가 → 물리적으로 눈에 띄므로 교수 이상 탐지·무작위 확인으로 대응.

## 4. V2(BLE) → V3(Flutter + 음향 토큰 + 신원 방어) 전환 사유

- **iOS 호환성**: BLE는 iOS Safari가 Web Bluetooth를 지원하지 않아 아이폰 사용자 인증이 붕괴됨. 교수 PC 브라우저도 BLE 비콘 송출 불가 → 별도 하드웨어 필요. **학생 측을 Flutter 네이티브 앱으로 전환**하고 근접성 신호를 **초음파 음향 토큰**으로 대체 → 교수 PC 기존 스피커만으로 배포, 전 기기 근접성 확보.
- **신원 방어 신설**: 1분 인증 창 + 서버 유일성 + 앱 생성 UUID 바인딩 + 학교 이메일 재인증.
- **스코프 정상화**: 결석 사유서 AI 자동 판독은 민감 건강정보·OCR 오판·책임 리스크로 핵심 범위에서 제외(v-next).
- **비용 최적화**: 상시 WebSocket → SSE/단발 푸시.
- **정직한 목표 서술**: "대리 출석 0%"가 아니라 "구조적으로 어렵고 대리 비용·발각 위험이 크며, 최종 확인은 교수".
- **개인정보 내재화**: Privacy-by-Design(동의·최소수집·보관기한·민감정보 회피).

## 5. 목표

동적 QR(시간)·초음파 토큰(공간)·신원 방어(1분 창+서버 유일성)·교수 확인(사람)의 계층 방어로 물리적·다계정 대리 출석을 구조적으로 어렵게 만들고 릴레이/우회 비용을 크게 높인다. Redis 캐싱 + Delta Batch UPDATE로 다수 강의실 동시 사용에서도 무결성과 응답성을 유지하며, 설계 단계에서 개인정보 보호 의무를 충족한다.
