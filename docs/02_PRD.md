## 4. 기능 요구사항

### FR-1 이중 인증 엔진
- 15초마다 갱신되는 동적 QR 토큰(Redis TTL)을 교수 PC 화면에 표시.
- 교수 PC 스피커가 15초마다 갱신되는 nonce를 실은 18~20kHz 음향 토큰 방출.
- 학생 Flutter 앱이 QR 스캔 + 마이크 음향 복호(FFT/대역 필터) 후 두 값을 함께 서버로 전송.
- 서버는 QR(시간/신원)과 음향 토큰(공간/근접성)을 모두 만족할 때만 교차 검증 통과.
- **FR-1.1 일회용 nonce(원격 릴레이 차단)**: 서버는 각 QR/음향 nonce를 **일회용(single-use)** 으로 처리하여 이미 사용·검증된 토큰의 재제출을 거부한다. 원본 소지자가 먼저 인증하면 토큰이 즉시 소모되어 릴레이 수신자는 재사용할 수 없다(15초 TTL과 결합해 릴레이 성공 비용을 크게 높임).

### FR-2 신원 위조(다계정 대리) 방어
- **FR-2.1 1분 인증 창**: 인증은 교수가 여는 약 60초 창 동안만 허용. 로그아웃 후 계정 전환 재인증 수법을 **현실적으로 어렵고 불안정하게** 만든다(완전 불가능 단정은 아니며 근본 차단은 FR-2.2 서버 유일성). 교수는 창을 연장/재개할 수 있음.
- **FR-2.2 서버 유일성 규칙**: 서버가 "한 세션당 계정 1회·동일 기기(UUID) 1회 출석"을 강제. 중복 시도 거부.
- **FR-2.3 앱 생성 UUID 기기 바인딩**: 앱이 최초 실행 시 랜덤 UUID 생성 → 키체인/키스토어(`flutter_secure_storage`·`flutter_udid`) 저장 → 최초 로그인 시 계정에 바인딩. 서버는 바인딩된 UUID와 일치하는 기기에서만 출석 인정.
- **FR-2.4 기기 변경 재등록 + 자동 바인딩 금지**: UUID 소실·기기 교체 시 곧바로 출석 불가. **새/미지의 UUID의 최초 바인딩은 반드시 학교 이메일(@wku.ac.kr) 재인증을 거쳐야 하며 자동 바인딩하지 않는다.** 인증(링크/코드) 통과 시 기존 바인딩을 새 UUID로 교체하고 변경 이력 로깅.
  - *알려진 경계(정직한 한계)*: 공격자가 **앱 데이터를 의도적으로 삭제**하면 같은 물리 기기라도 새 UUID가 생성되어 서버에는 "새 기기"로 보인다. 자동 바인딩 금지 + 이메일 재인증 강제로 UUID 재생성만으로 유일성 규칙을 즉시 우회할 수 없게 하며, 재인증 후 반복 스와핑은 교수 이상 탐지 대상으로 둔다.
- **FR-2.5 프론트엔드 UX 넛지**: 계정 전환 시도 시 가벼운 확인 창만 표시. 하드 로그아웃 쿨타임·세션 강제 잠금은 두지 않음(서버 규칙과 중복, 정상 사용자 오탐).
- **FR-2.6 생체인증(선택)**: 출석 순간 Face ID/지문 챌린지 서명(WebAuthn/FIDO 원리)은 향후 확장 옵션. 필수 아님.

### FR-3 트래픽 병목 해결 (피크/마감 분리)
- **(A) 수업 시작 피크(동시 인증 쓰기)**: 단기 토큰(nonce)·세션 상태를 Redis 원자 연산(`SET NX`, 카운터)으로 처리해 PostgreSQL 행 락 경합을 피하고, 개별 인증은 가벼운 append로 받는다.
- **(B) 마감 시점**: 전원이 아닌 미인증자(Delta)만 Batch UPDATE.
- 조회성 데이터(누적 결석 등)는 Redis 선캐싱으로 SELECT 스탬피드 완화.

### FR-4 학사 관리 / 위험군 경고
- 인증 직후 누적 결석 조회, 위험군(예: 3회)에 SSE 또는 인증 응답 포함 단발 푸시로 경고.

### FR-5 교수 인 더 루프 폴백
- 근접성 신호 실패(마이크 권한 거부, 소음, 저가 마이크, 기기 문제)나 1분 창을 놓친 정당한 학생(지각·느린 스캔·배터리 방전)이 자동 결석으로 직결되지 않음.
- 미인증자는 결석자 목록에 표시되되 교수가 인증 창을 연장·재개하거나 대시보드에서 즉석 확인·정정.

### FR-6 개인정보(Privacy-by-Design)
- 최초 사용 시 수집 항목(출결, 근접성 신호, 기기 정보)·목적 고지 및 동의.
- 위치·음향 원자료 미저장, "근접성 검증 통과 여부(boolean)"만 기록, 음향 토큰은 세션 후 폐기.
- 기기 변경 이력은 이상 탐지 목적 로그로 보관. 출결 데이터는 학사 규정 기한까지만 보관 후 파기.
