## 2. 인증 흐름 (이중 인증 + 신원 방어 + 교차 검증)

1. 교수가 출석 시작 → 서버가 세션 생성, **1분 인증 창** 오픈, Redis에 15초 TTL QR 토큰·음향 nonce 발급.
2. 교수 PC: 화면에 QR 표시 + 스피커로 18~20kHz 음향 토큰(nonce) 방출(15초마다 갱신).
3. 학생 앱: QR 스캔 + 마이크 음향 복호 → QR 값 + 음향 nonce + **기기 UUID**를 서버로 전송.
4. 서버 검증 순서:
   - **인증 창 유효성**: 현재 세션의 60초 창 안인가.
   - **교차 검증**: QR(시간/신원) + 음향 nonce(공간/근접성)를 Redis 기준으로 모두 만족하는가.
   - **일회용 nonce 검사**: 해당 QR/음향 nonce가 아직 소모되지 않았는가(이미 사용된 토큰의 재제출이면 거부). 통과 시 즉시 소모 처리.
   - **기기 바인딩**: 전송된 UUID가 해당 계정에 바인딩된 UUID와 일치하는가.
   - **유일성 규칙**: 이 세션에서 해당 계정·해당 UUID가 아직 출석하지 않았는가.
   - 모두 통과 시에만 출석 인정(중복/불일치/창 만료/재사용 시 거부).
5. 인증 직후 누적 결석 조회 → 위험군이면 SSE로 경고.

> 음향은 벽을 크게 넘지 못하고 nonce가 15초마다 바뀌며 **일회용(single-use)으로 소모**되어, 캡처·전달한 토큰을 릴레이 수신자가 재사용할 수 없다. 여기에 60초 창 + 계정/기기 유일성이 더해져 원격 릴레이와 1기기 다계정 수법을 시간적·구조적으로 차단한다.

## 3. 기기 바인딩 & 재등록

- **최초 로그인**: 앱이 생성해 키체인/키스토어에 저장한 UUID를 계정에 바인딩(`device_bindings` 테이블에 account_id ↔ uuid 기록).
- **기기 변경/UUID 소실**: 새 기기에서 곧바로 출석 불가 → 학교 이메일(@wku.ac.kr) 인증 링크/코드 통과 시 서버가 바인딩을 새 UUID로 교체하고 변경 이력을 로그로 남김(이상 탐지 활용).
- **자동 바인딩 금지(앱 데이터 삭제 경계)**: 앱 데이터를 삭제하면 같은 물리 기기라도 새 UUID가 생성되어 서버에는 "새 기기"로 보인다. 따라서 **새/미지의 UUID의 최초 바인딩은 반드시 이메일 재인증을 거치며 자동 바인딩하지 않는다.** UUID 재생성만으로는 유일성 규칙을 즉시 우회할 수 없고, 재인증 마찰 + 이력 로깅이 추가된다. 재인증 후 반복 스와핑은 교수 이상 탐지 대상.
- **근거**: 하드웨어 ID는 OS가 차단, `device_info_plus` OS 식별자(IDFV/SSAID)는 재설치·초기화로 변해 바인딩 기준으로 부적합 → 앱 통제 UUID 사용(보안 목적 `device_info_plus` 미사용).

## 4. 데이터 병목 대응 (피크/마감 분리)

트래픽 부하는 성격이 다른 두 국면으로 나눠 대응한다.

- **(A) 수업 시작 피크 — 동시 인증 쓰기 경합**: 인증 검증에 필요한 단기 토큰(QR·음향 nonce)·세션 상태를 **Redis 원자 연산(`SET NX`, 카운터)** 으로 처리해 PostgreSQL 행 단위 락 경합을 피하고, 개별 인증은 가벼운 append 성격으로 받아 쓰기 경합을 최소화.
- **(B) 마감 시점 — Delta-based Batch UPDATE**: 마감 시 전원이 아닌 미인증자(변경분 Delta)만 묶어 한 번에 Batch UPDATE → 락 점유·I/O 최소화.
- **조회 캐시**: 누적 결석 등 조회성 데이터는 Redis 선캐싱으로 PostgreSQL SELECT 스탬피드 완화.

## 5. 실시간 (SSE)

- 위험군 경고(학생)·실시간 출석 현황(교수)을 단방향 저비용 SSE(또는 인증 응답 포함 단발 푸시)로 전송. WebSocket 상시 연결은 비핵심 선택 확장.

## 6. 신뢰성·폴백

- 근접성 신호 실패나 1분 창을 놓친 정당 학생은 자동 결석이 아님. 교수가 창 연장·재개 또는 즉석 정정(교수 인 더 루프).
- 잔여 리스크(강의실 내 공범 중계, 음향 재생 스푸핑, 친구 폰 여러 대)는 완전 차단 불가로 명시하고 교수 이상 탐지·무작위 확인으로 보완.

## 7. 배포

- Docker로 환경 통일. 교수 대시보드 Vercel, 백엔드 Render 등으로 CI/CD 배포. 학생 앱은 Flutter 빌드(iOS/Android).
