## 2. 핵심 기술 요구사항

### TR-0 [최대 리스크] 음향 실현 가능성 선검증
- 노트북 스피커의 18~20kHz 준-초음파 방출 + 다양한 학생 기기 마이크의 강의실 거리·소음 복호 가능성을 **M1~M2 초기 feasibility spike**로 우선 검증.
- 신뢰도 부족 시 대체안: 가청 대역 하단(거슬림이 적은 대역) 또는 화면 표시 보조 신호. 대체안 채택 시에도 QR·교차검증·신원 방어·SSE 등 나머지 설계는 그대로 유효.

### TR-1 이중 인증 / 교차 검증
- Redis 15초 TTL 기반 동적 QR 토큰 발급.
- 18~20kHz 준-초음파 음향 토큰(nonce) 발급/방출/검증. 15초 갱신.
- 서버는 QR + 음향 nonce를 세션 기준 교차 검증.
- **일회용 nonce**: 각 nonce는 검증 시 즉시 소모(consume-on-verify), 재제출은 거부 → 캡처·전달 토큰의 원격 릴레이 차단.

### TR-2 신원 방어 (다계정 대리)
- **1분 인증 창**: 세션당 약 60초 창, 교수 연장/재개 가능(Redis로 창 상태 관리).
- **서버 유일성 규칙**: "세션당 계정 1회·기기 UUID 1회 출석" DB 제약/검사로 강제(예: (session_id, account_id) 및 (session_id, device_uuid) 유니크).
- **앱 생성 UUID 바인딩**: 앱 최초 실행 시 UUID 생성 → 키체인/키스토어 저장 → `device_bindings`에 계정 바인딩. `device_info_plus` OS 식별자는 보안 목적 미사용.
- **기기 변경 재등록 + 자동 바인딩 금지**: 학교 이메일(@wku.ac.kr) 인증 코드/링크 검증 후 바인딩 교체 + 이력 로깅. 새/미지의 UUID의 최초 바인딩은 자동으로 하지 않고 반드시 이메일 재인증(앱 데이터 삭제로 UUID가 재생성되는 경계 방어).
- **프론트 UX 넛지**: 계정 전환 확인 다이얼로그만. 하드 쿨타임/세션 잠금 없음.
- **생체인증**: 선택 확장(WebAuthn/FIDO 원리), 필수 아님.

### TR-3 음향 송수신
- 교수: PC 스피커로 nonce 인코딩 신호 방출(별도 하드웨어 불필요).
- 학생: Flutter 앱 마이크로 캡처 후 FFT/대역 필터로 nonce 복호.
- 실환경(강의실 소음·거리·기기별 마이크) 감지율 검증 필요.

### TR-4 트래픽 최적화 (피크/마감 분리)
- **(A) 피크 인증**: 단기 토큰(nonce)·세션 상태를 Redis 원자 연산(`SET NX`, 카운터)으로 처리해 PostgreSQL 행 락 경합 회피, 개별 인증은 가벼운 append.
- **(B) 마감**: Delta-based Batch UPDATE — 미인증자(변경분)만 UPDATE → 락 점유·I/O 최소화.
- Redis 선캐싱으로 SELECT 스탬피드 완화. 동시 인증·마감 부하 테스트로 검증.

### TR-5 실시간 경고
- 인증 직후 누적 결석 조회 → 위험군에 SSE 또는 응답 포함 단발 푸시.

### TR-6 개인정보
- 원자료 미저장(boolean만 기록), 음향 토큰 세션 후 폐기, 앱 생성 UUID 외 기기 식별자 미수집, 규정 기한 보관 후 파기.
