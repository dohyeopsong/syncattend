## 📋 레이어별 상세

### 백엔드: 33개 엔드포인트, 121개 테스트

**완전 구현 (15/15 요구사항):**
- Auth (register/login/me/refresh), @wku.ac.kr 검증
- 기기 UUID 바인딩 + 재인증 (이메일 코드)
- 코스 CRUD + 시간표 + 카탈로그 + 수강신청
- 세션 관리 (open/extend/close/token) + week_number
- 토큰 서비스 (issue/cross_verify/rotation, SET NX 의도적 제거)
- 출석 4단계 검증 + 집계 + delta 마감 + 수동 정정
- 결석 위험 경고 (임계값 설정 가능) + SSE

**유일한 스텁:**
- `email_codes.py:_deliver()` — 코드를 로그만 출력, 실제 이메일 미발송

### 웹: 2 페이지, 6 컴포넌트, 4 스토어

**완전 구현:** 로그인, 대시보드, 코스 CRUD, 세션 관리, QR+초음파 송출, SSE 실시간, 출결 검토

**개선 필요:**
- Refresh Token 갱신 로직 없음
- 누적 결석 위험 UI 없음 (세션 레벨만)
- 웹용 시간표 그리드 없음 (코스 목록에 인라인 표시만)

### 모바일: 9 화면, 14 API 호출

**완전 구현:** 로그인, 기기 바인딩/재인증, 홈, 출석 인증, 출결 이력, 시간표, 강의 카탈로그, SSE 위험 배너

**개선 필요:**
- 문의 화면 placeholder (하드코딩 메시지)
- 오디오 config 불일치 (18-20kHz 표기, 17-18.5kHz 실사용)
- 0.5s 회전 경계 클라이언트 처리 없음
- 오디오 디코더 "spike-level" 성숙도

### 계약/인프라

**OpenAPI:** 28개 경로 정의, 5개 gap (course_schedules 3개 + schedule_id + Health 불일치)
**마이그레이션:** SQL 4개 + Alembic 4개, models.py와 일치
**Docker:** postgres+redis+backend (web 없음), alembic 미실행
**CI:** 3-job (backend pytest, web build, mobile test) — Postgres 미사용
