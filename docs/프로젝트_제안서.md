# Syncattend V3 — 스마트 출결·학사관리 플랫폼 프로젝트 제안서

> 본 문서는 프로젝트의 확정 제안서(V3)입니다. 초기안(QR 보류·WebSocket 중심)과 V2(BLE 이중인증)는 아래 사유로 대체되었습니다.

## 1. 프로젝트 소개

학생과 교수가 편리하게 사용하고, **대리 출결을 시스템 구조로 어렵게 만드는** 출결·학사관리 시스템을 만든다.

- 학생은 **Flutter 네이티브 모바일 앱**으로 QR 스캔 + 마이크 음향 토큰 감지로 출석을 인증하고 자신의 출결을 확인한다.
- 교수는 **React 웹 대시보드**에서 수업과 출결을 관리하고, PC 화면(QR)·스피커(음향 토큰)만으로 인증을 운영한다.
- 출결·학사 정보를 통합 저장하여 확인·관리가 쉽도록 한다.

## 2. 필요성

- 정적 QR은 화면 캡처·공유로 강의실 밖 원격 인증이 가능한 구조적 취약점이 있다.
- QR·음향은 근접성만 증명할 뿐 "조작자가 계정 주인인가"라는 신원은 증명하지 못해 1기기 다계정 대리가 가능하다.
- 학사-출결 분리로 수기/엑셀 처리 실수·행정 부담이 크다.
- 수업 시작 시간대 동시 접속으로 DB 병목·락 경합이 발생한다.

## 3. 계층 방어 (핵심)

| 계층 | 신호 | 메커니즘 |
|------|------|----------|
| 시간·신원 | 동적 QR | 15초 TTL 회전 토큰(Redis), 교수 PC 화면 |
| 공간·근접성 | 초음파 음향 토큰 | 18~20kHz nonce, 교수 PC 스피커 → 학생 Flutter 앱 마이크 복호 |
| 신원(다계정 방어) | 1분 창 + 서버 유일성 + 기기 바인딩 | 60초 창, 세션당 계정·UUID 1회, 앱 생성 UUID 바인딩 |
| 사람 | 교수 확인 | Opt-out 대시보드, 미인증=교수 확인·정정·창 연장 |

> **원격 릴레이 차단 메커니즘**: QR·음향 토큰(nonce)은 15초마다 갱신되고, 서버가 **각 nonce를 일회용(single-use)으로 처리해 재제출을 거부**한다. 원본 소지자가 먼저 인증하면 토큰이 즉시 소모되어 릴레이 수신자가 재사용할 수 없고, 화면 QR과 음향을 동시에 포착·중계해야 하므로 성공 비용이 급격히 커진다.

> **핵심 기술 가정(선검증 대상)**: "노트북 스피커의 18~20kHz 방출 + 다양한 학생 기기 마이크의 강의실 거리·소음 복호"는 확정 사실이 아니라 **본 프로젝트 최대의 기술 리스크이자 선결 검증 항목**이다. M1~M2 초기에 실현 가능성 테스트로 우선 검증하고, 신뢰도가 부족하면 가청 대역 하단·화면 보조 신호 대체안을 준비한다.

## 4. 사용자별 주요 기능

### 4.1 학생용 앱 (Flutter)
- 로그인, 최초 기기 등록(앱 생성 UUID 바인딩), 기기 변경 시 학교 이메일(@wku.ac.kr) 재인증
- 시간표 확인
- 출석 인증(QR + 음향 토큰), 인증 창 카운트다운
- 내 출결 확인, 위험군 경고 수신(SSE), 출결 문의

### 4.2 교수용 웹 (React)
- 로그인, 수업/시간표 설정
- 출석 창 시작/연장/종료, QR 표시 + 음향 토큰 송출
- 실시간 출석률·미인증자 확인, Opt-out 정정(Delta Batch UPDATE)
- 출결 문의 확인·답변

## 5. 신원 위조(다계정 대리) 방어

- **1분 인증 창**: 교수가 여는 약 60초 동안만 인증 가능 → 로그아웃 후 친구 계정 재인증을 **현실적으로 어렵고 불안정하게** 만든다(불가능 단정은 아니며 근본 차단은 서버 유일성). 교수 연장 가능.
- **서버 유일성 규칙(핵심)**: 서버가 "세션당 계정 1회·기기 UUID 1회"를 강제.
- **앱 생성 UUID 기기 바인딩**: `flutter_secure_storage`/`flutter_udid`로 키체인/키스토어에 UUID 저장·바인딩. 하드웨어 ID는 OS 차단, `device_info_plus` OS 식별자는 재설치·초기화로 변해 부적합 → 보안 목적 미사용.
- **기기 변경 재등록**: 학교 이메일(@wku.ac.kr) 재인증으로만 새 기기 재바인딩, 이력 로깅.
- **알려진 경계(정직)**: 앱 데이터를 삭제하면 같은 폰이 새 UUID로 보일 수 있으므로, **새 UUID 최초 바인딩은 반드시 이메일 재인증을 강제(자동 바인딩 금지)** 하고 재인증 후 반복 스와핑은 교수 이상 탐지로 대응.
- **프론트엔드는 UX 넛지만**: 하드 쿨타임·세션 잠금은 서버 규칙과 중복·오탐이라 두지 않음.
- **생체인증은 선택 확장**, **여러 폰 지참은 교수 이상 탐지**로 대응.

## 6. 개발 기술

| 부분 | 사용할 기술 |
|---|---|
| 학생용 앱 | Flutter (네이티브) |
| 교수용 웹 | React (shadcn/ui, Zustand) |
| 백엔드 서버 | Python / FastAPI (async) |
| 데이터베이스 | PostgreSQL(영구) + Redis(단기 토큰/창/캐시) |
| 실시간 통신 | SSE (WebSocket은 선택적 확장) |
| 인프라 | Docker, Vercel/Render CI/CD |

## 7. 신뢰성·성능·개인정보

- **트래픽 대응(피크/마감 분리)**: (A) 수업 시작 피크의 동시 인증 쓰기는 단기 토큰·세션 상태를 **Redis 원자 연산(`SET NX`·카운터)** 으로 처리해 PostgreSQL 행 락 경합을 피하고, (B) 마감 시점은 **상태 변경분(미인증자 Delta)만 Batch UPDATE** 한다. 조회성 데이터는 Redis 선캐싱으로 SELECT 부하를 완화한다.
- **교수 인 더 루프 폴백**: 신호 실패·1분 창 놓침이 자동 결석이 아님. 미인증자는 결석자 목록에 표시되되 교수가 창 연장·정정.
- **Privacy-by-Design**: 동의, 위치·음향 원자료 미저장(boolean만), 음향 토큰 세션 후 폐기, 규정 기한 보관 후 파기, 진단서 등 민감정보 자동 판독 안 함(교수 수동 처리).

## 8. 수행 일정 (6 마일스톤)

- **M1**: 환경·DB·인증 뼈대, API 명세(기기 등록/유일성/인증 창 포함), Mock UI.
- **M2**: QR + 음향 교차검증, Redis 세션, 1분 창, 서버 유일성, UUID 바인딩·이메일 재등록 API, 송수신 연동.
- **M3**: 출결 집계 API, 위험군 경고(SSE), 교수 대시보드(Delta 추출).
- **M4**: 학생·교수 전체 시나리오 통합, 교수 폴백·창 연장, 계정 전환 UX 넛지.
- **M5**: 보안 점검(신원 방어 우회 시도 포함), E2E, Delta Batch 부하 테스트, 음향 실환경 테스트.
- **M6**: 배포, Privacy 정책 문서화, 산출물·데모.

## 9. 범위 밖 / 연기

- **연기(v-next)**: 결석 사유서 AI 자동 판독, 생체인증 서명.
- **범위 밖**: BLE 비콘 근접성(iOS 미지원)→음향 토큰 대체, 보안 목적 `device_info_plus`, 하드 프론트 로그아웃 쿨타임, 절대적 대리출석 차단.

## 10. 기대 효과

- 정직하게 출석하는 학생의 권리를 보호하고 공정한 평가 기반 마련.
- 자동 집계·Opt-out·Delta 처리로 행정 효율 극대화.
- 출결 패턴(익명·집계) 기반 위험군 조기 판별, 타 기관 확장(모듈형).
